# Semantic Scholar API Usage Plan

Our **Body Peptide Map** is an interactive web application designed for researchers and medical professionals to explore peptide research comprehensively by integrating Semantic Scholar API to enable real-time scholarly article discovery, connecting peptide therapeutics data with peer-reviewed scientific literature. We utilize the `/paper/search` endpoint, requesting title, authors, year, citation count, abstract, external IDs (DOI, PubMed), URL, and paper ID to rank papers by influence and assess relevance, with current usage expectations of 50-100 API calls/day during development with 2-5 simultaneous users and production scaling to 500-1000 calls/day for an estimated 100-200 active users with burst capacity for 50+ concurrent requests during peak hours. Our request structure prioritizes efficiency through batched queries that combine multiple peptide searches into single API transactions (e.g., "(GLP-1 OR BPC-157 OR TB-500) AND clinical trial"), field filtering to request only essential data and reduce payload size by ~40%, aggressive caching strategies that store results for 7 days to avoid redundant calls, and rate limiting implementation that queues requests to stay within API limits with 100ms delays between calls. Integration points include our search panel where users query for peptide research and we supplement our initial database of 500+ manually-curated studies with real-time Semantic Scholar results ranked by relevance and citation count, deduplication logic that compares DOI and normalized titles to prevent duplicates across multiple API sources, and analytics tracking that monitors which peptides researchers search for most to identify gaps and inform future curation. Efficiency optimizations employ client-side deduplication using Sets to track DOIs and normalized titles, progressive loading that displays PubMed results immediately while asynchronously appending Semantic Scholar results, throttled searches with 500ms debouncing to prevent duplicate requests, and graceful degradation that falls back to our manual database if the API becomes unavailable. Expected user benefits include access to 200M+ papers across all scientific disciplines, real-time discovery of new peptide research with confidence through citation metrics, and automated deduplication across multiple sources, while project benefits include ~30% reduction in manual curation workload, ability to identify trending research topics, quality assurance through citation metrics, and a scalable knowledge base that grows without manual effort. We remain fully compliant with Semantic Scholar's terms of service, staying within the 100,000 requests/month free tier limit, displaying proper attribution to Semantic Scholar API in results, implementing robust error handling with graceful degradation, and maintaining user privacy by only transmitting peptide names and medical terms to the API without any personal data.
